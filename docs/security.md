# Безпека системи моніторингу насосів

## Доступ до брокера

Mosquitto вимагає ім’я користувача й пароль. У Docker Compose порт 1883
опубліковано на `127.0.0.1` для доступу з локального комп’ютера. Контейнери
підключаються до брокера за іменем `broker` у мережі Compose.

| Обліковий запис | Дозволені дії |
|---|---|
| `pump-01` | Публікація у `plant/+/+/pump-01/#`. |
| `pump-02` | Публікація у `plant/+/+/pump-02/#`. |
| `ingest` | Читання `plant/#`. Сервіс підписується на телеметрію своєї лінії. |
| `alerts` | Читання `plant/+/+/+/telemetry` і публікація у `plant/+/+/+/alerts`. |

## Загрози та захист

| Загроза | Як система її обмежує |
|---|---|
| Підключення стороннього клієнта | Брокер перевіряє облікові дані. Анонімний доступ вимкнено через `allow_anonymous false`. |
| Публікація від імені іншого насоса | ACL обмежує запис гілкою відповідного `device_id`. |
| Зміна телеметрії | За заданого `SIGNING_KEY` шлюз підписує повідомлення. Приймач перевіряє підпис із фактичним MQTT-топіком перед записом у SQLite. |
| Повтор підписаного повідомлення | Приймач перевіряє часову позначку та зберігає використані `nonce` у кеші. Повторний `nonce` у межах часу дії кешу спричиняє відхилення. |

## Налаштування та межі захисту

Паролі клієнтів і спільний ключ підпису зберігаються локально в `deploy/.env`.
Брокер використовує `deploy/passwd` для перевірки паролів і `deploy/acl` для
перевірки прав. У репозиторії `deploy/.env.example` містить порожні поля.

У цій конфігурації MQTT працює без TLS. Підпис захищає цілісність повідомлення,
але його вміст передається відкритим текстом. Ключ підпису спільний для сервісів,
тому його розкриття дозволило б створювати підписані повідомлення.

## Результати перевірки

- Брокер відхилив анонімне підключення.
- `pump-01` опублікував повідомлення у власний топік, а `ingest` його отримав.
- Спробу `pump-01` опублікувати в топік `pump-02` брокер відхилив із кодом 135.
- Телеметрія з правильним підписом потрапила в SQLite. Повідомлення,
  підписане іншим ключем, приймач відхилив із помилкою `InvalidSignature`.
- Повторна перевірка того самого підписаного повідомлення з тим самим
  кешем завершилася помилкою `ReplayError`.
